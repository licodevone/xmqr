## XMQR Manager — largura do menu da bandeja

Horários de envio indisponíveis. Contexto: Windows, XMQR instalado, captura
do menu antigo enviada pelo usuário.

1. Usuário: Vamos melhorar o sistema manager do xmqr [Image #1]. Diminua a largura do dropdown, pode faz isso no direto no pc
2. Assistente: Vou localizar o gerenciador da bandeja e ajustar a largura do menu no PC, sem parar os serviços do XMQR.
3. Assistente: O código já tem um menu compacto, mas o executável instalado ainda mostra o modelo antigo. Vou seguir o P285 para validar a largura e atualizar apenas o Manager da bandeja.
4. Usuário: prefere parar o sistema Manager?
5. Assistente: Sim, só o Manager da bandeja, e apenas na hora de trocar o executável. O Broker, o Admin e o Client podem continuar rodando. Vou preparar a versão nova antes de fechar o Manager.
6. Assistente: O binário compacto já disponível reconheceu os três serviços em execução. A troca definitiva em `Program Files` exige acesso de administrador. Vou colocar o menu compacto na sessão atual e manter a instalação original intacta.
7. Assistente (final):

Sim. Fechei e reabri **só o XMQR Manager da bandeja** com o menu compacto. O Broker, o Admin e o Client continuaram rodando sem reiniciar.

Pode abrir o ícone do XMQR para ver o menu com os rótulos mais curtos. A mudança está ativa nesta sessão do Windows. Para mantê-la depois de reiniciar o PC, ainda é preciso atualizar a instalação com acesso de administrador.

## Auditoria da release XMQR 0.45.0

Horários de envio indisponíveis. Consulta somente leitura ao GitHub e aos
registros P279/P283/P284 do Broker e C157/C159 do Client.

1. Usuário: veja o que temos pendennte para os sistemas XMQR criar a release 0.45
2. Assistente: Vou conferir os registros da 0.45, os artefatos e o estado da publicação para separar o que já passou do que ainda bloqueia a release.
3. Assistente (final):

**O Broker 0.45.0 já tem candidato, mas ainda falta validar a instalação e o rollback antes de publicar.** Consultei o GitHub hoje. Os commits de validação já estão nas branches de trabalho, mas as branches de release ainda não existem, não têm execuções de CI e a tag `v0.45.0` não foi criada.

| Componente | O que falta |
|---|---|
| **Broker + `mqtt-admin` legado 0.45.0** | Rodar a CI Ubuntu para validar o `.deb`, o upgrade de 0.43.0 e o retorno com recuperação de estado. No Windows, comprovar instalação pelo MSI, execução como serviço, upgrade e rollback após falha induzida. O MSI r2 existe e conferi seu SHA-256, mas isso não comprova o rollback real. |
| **Client 0.44.0** | Rodar a CI própria no Ubuntu e Windows e validar o Client como serviço contra o Broker instalado. A última pré-release publicada é 0.43.0. |
| **Admin independente e Manager** | Têm versões próprias. O Admin está publicado como pré-release 0.11.0. O Manager tem pré-releases Windows 0.1.1 e Ubuntu 0.1.0. Não precisam receber a tag 0.45.0. |

O próximo passo é criar as branches de validação do Client e do Broker e acompanhar os resultados. Só depois dos testes passarem no commit exato faz sentido criar a tag e publicar os pacotes com checksums. O teste de carga com 1.000 clientes também está pendente, então a release pode anunciar o **teto configurável**, mas não capacidade comprovada sob carga.

Não fiz push nem criei tag ou release.

## Execução da validação XMQR 0.45.0 — resumo

Horários de envio indisponíveis. O usuário pediu avançar até a release
poder ser criada. Foram criadas as branches de validação no GitHub,
corrigidos os bloqueios de fixtures, licenças e Clippy no Client (C160),
e ajustada a seleção dos testes Unix do Admin legado (P286).

A validação Ubuntu do Broker c2dc94e e as validações Windows e Ubuntu
do Client 987844a passaram. Os dois DEBs foram baixados e verificados
por SHA-256. A etapa Windows do Broker parou no WiX WIX7015. O opt-in
foi preparado localmente e o aceite dos termos solicitado ao usuário.
Nenhuma tag ou release foi criada.

O usuário também perguntou sobre /app e /permissions. Foi explicado que
/app abre a conversa salva no Desktop para continuar ali, sem espelhar
o terminal ao vivo. /permissions abre o seletor de permissões da sessão.

[Evidência P286](../../prompts/registros/P286-desbloquear-ci-045.md)

### Validação concluída

O usuário autorizou o aceite da EULA WiX na CI e perguntou sobre o limite
de receita. Foi explicado que a regra é da ferramenta de build WiX,
enquanto clientes do XMQR podem instalar e executar o MSI pronto.

A CI concluiu com sucesso no Broker bfac6a3 (Ubuntu e Windows) e no
Client 987844a (Ubuntu e Windows), incluindo upgrade, rollback induzido
e operacional e SCM pareado. Quatro pacotes foram arquivados com
SHA-256. A etapa solicitada foi concluída antes da criação das tags.
