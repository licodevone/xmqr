Seção 8 — XMQR Admin web: instalação, acesso e operação

Atualização didática de 19/10/2026. Esta seção complementa o snapshot histórico das aulas anteriores; não transforma código antigo em uma release nova. Os comandos são instruções para o aluno: não comprovam instalação, configuração ou funcionamento no seu computador.

Aula 8.1 — Entenda os três softwares, as portas e as versões

Passo 1 — Diferencie broker, client, admin e monitor HTTP

ComponenteFunçãoEndereço do exemplo
mqtt-broker / XMQR brokerRecebe conexões, autentica, aplica ACL e distribui mensagens MQTT entre publicadores e assinantes.MQTT com TLS em 8883; o endereço de rede depende da instalação.
mqtt-client / XMQR clientpub publica e sub escuta tópicos. O admin também executa esse client como processo filho.Conecta ao broker; não cria uma porta de servidor para cada comando.
xmqr-adminServe a interface web, contas locais, métricas e console MQTT autorizado.http://127.0.0.1:9080 no navegador do Windows.
Monitor do brokerAPI HTTP local de prontidão e métricas; não é o painel gráfico.http://127.0.0.1:9090/ready e /metrics.

O fluxo do painel é navegador → HTTP/JSON do admin → monitor HTTP ou processos mqtt-client → broker MQTT. O ESP32 publica no broker e o console pode assinar o mesmo tópico. No ESP32, 127.0.0.1 representa o próprio dispositivo: utilize o endereço do computador e o nome/IP autorizado pelo certificado.

O painel usa HTML, CSS e JavaScript nativos; o servidor usa Rust, Axum e Tokio. Não exige Node.js, PostgreSQL, compilação React ou instalação de um WebSocket no broker para este caminho. Esses serviços pertencem a outros projetos do curso. MQTT, HTTP, WebSocket e Wi-Fi são tecnologias distintas: Wi-Fi dá acesso à rede; HTTP atende páginas/APIs; WebSocket mantém um canal de mensagens sobre uma conexão HTTP atualizada; MQTT define a comunicação por tópicos. Aqui o navegador usa HTTP e os filhos do admin usam MQTT/TLS.

Aula 8.2 — Abra o WSL e execute o binário da fonte correta

Passo 1 — Entre no Ubuntu e confira instalações e caminhos

No PowerShell do Windows:

wsl --list --verbose
wsl -d Ubuntu-26.04

--list --verbose lista distribuições instaladas e seu estado; -d abre a distribuição indicada. Se o nome listado for outro, use o nome real. Os próximos blocos Bash são executados dentro do Ubuntu, não no PowerShell.

uname -a
dpkg --print-architecture
mqtt-broker --version
mqtt-client --version
xmqr-admin --version
command -v mqtt-broker
command -v mqtt-client
command -v xmqr-admin
dpkg-query -W xmqr-broker xmqr-client xmqr-admin

uname identifica o sistema Linux; dpkg --print-architecture informa a arquitetura, como amd64. Os três comandos --version consultam executáveis no PATH; command -v informa quais caminhos serão usados. dpkg-query -W consulta pacotes Debian; um executável compilado manualmente pode existir sem constar nessa lista. “Comando não encontrado” ou pacote ausente não confirma que outros componentes estejam instalados.

Um caminho Windows D:\projects\my-project\acmebr-projects\acmebr-broker-client aparece no Ubuntu como /mnt/d/projects/my-project/acmebr-projects/acmebr-broker-client. Você continua executando no Linux mesmo acessando arquivos da unidade D. Guarde credenciais e estado privado em $HOME do Linux; permissões 600/700 em /mnt/d dependem da montagem do WSL.

Para instalar releases Debian já verificadas, entre na pasta dos artefatos .deb e confira os respectivos .sha256 com sha256sum -c arquivo.deb.sha256 antes de sudo apt install ./arquivo.deb. Use o nome real do artefato e a arquitetura correta; .dev não é o sufixo desse instalador. Não reaproveite nomes de versões antigas como se fossem atuais. Este passo não torna o pacote admin 0.11.0 equivalente à fonte A25.

Passo 2 — Compile a fonte recente sem substituir o pacote instalado

Use uma cópia do repositório admin que contenha 4c664cf ou um sucessor aceito. O comando de ancestralidade recusa uma fonte anterior. Confira alterações locais antes de compilar; não descarte trabalho nem troque de branch automaticamente.

cd /mnt/d/projects/my-project/acmebr-projects/acmebr-broker-client/xmqr-admin
git log -1 --oneline
git status --short
git merge-base --is-ancestor 4c664cf HEAD
rustc --version
cargo --version
env -u CARGO_TARGET_DIR cargo build --locked --release
export XMQR_ADMIN_BIN="$PWD/target/release/xmqr-admin"
"$XMQR_ADMIN_BIN" --version

cd seleciona o projeto independente; git log mostra a fonte e git status revela modificações. merge-base --is-ancestor retorna código zero se o commit necessário faz parte da história atual; se falhar, pare e obtenha a fonte correta. rustc e cargo verificam as ferramentas ensinadas no módulo de instalação Rust, respeitando o mínimo do manifest.

cargo build --locked --release compila com o lockfile existente e otimizações, sem atualizar dependências deliberadamente. env -u CARGO_TARGET_DIR remove essa variável somente da compilação, fazendo a saída ir para o target/release local indicado. Execute a linha seguinte somente após compilação bem-sucedida. XMQR_ADMIN_BIN aponta explicitamente para o binário dessa fonte, evitando executar o pacote antigo por engano. O número de versão continua exigindo a conferência do commit.

Uma atualização da interface web pode exigir apenas compilar e reiniciar o admin. Não instale novamente o broker/client, não reinicie MQTT e não regrave o ESP32 para trocar HTML/CSS/JS do painel. A prévia local deste checkpoint foi reiniciada após reset com um token novo, sem perfis MQTT restaurados; o próprio usuário faz o primeiro cadastro no navegador. Isso descreve aquela prévia, não comprova a configuração de outra máquina.

Aula 8.3 — Verifique o broker e entenda os logs do serviço

Passo 1 — Consulte prontidão, métricas e o serviço existente

systemctl status xmqr-broker.service --no-pager
curl -i --max-time 5 http://127.0.0.1:9090/ready
curl --max-time 5 http://127.0.0.1:9090/metrics

systemctl status consulta a unidade systemd, quando ela existe e systemd está disponível no WSL. Não cria serviço. curl faz a requisição HTTP; -i inclui cabeçalhos e --max-time 5 limita a espera. HTTP 200 em /ready indica prontidão naquele momento; 503 indica que a verificação não aprovou o broker. Conexão recusada significa que não houve resposta nesse endereço, não uma prova isolada de que todo o MQTT morreu.

Se o broker ainda não estiver configurado, siga primeiro o módulo de instalação/TLS/ACL correspondente. Não existe garantia de que /etc/xmqr/broker.env esteja presente depois de um reset. Quando esse arquivo pertence à sua instalação existente, confira-o com sudoedit /etc/xmqr/broker.env, preservando certificados, autenticação, ACL e estado. As linhas opcionais de monitor são:

MQTT_MONITOR_ENABLED=true
MQTT_MONITOR_BIND=127.0.0.1:9090

Somente se você alterou a configuração do seu serviço e pode interromper suas conexões, aplique com sudo systemctl restart xmqr-broker.service. O reinício interrompe temporariamente os clientes MQTT. Não é necessário para apenas abrir ou atualizar o admin web.

Passo 2 — Leia journalctl e diagnostique a primeira falha

journalctl -u xmqr-broker.service -n 50 --no-pager
ParteO que faz
journalctlLê o diário do systemd; não reinicia nem modifica o broker.
-u xmqr-broker.serviceFiltra mensagens da unidade indicada.
-n 50Mostra as últimas cinquenta linhas disponíveis.
--no-pagerImprime diretamente no terminal, sem abrir um paginador.

Se faltar permissão de leitura do diário, use o mesmo comando com sudo. Procure a primeira causa útil: arquivo ausente, permissão incorreta, porta ocupada, certificado inválido, variável obrigatória ou estado incompatível. status=1/FAILURE sozinho informa a saída com erro, não sua causa. Logs do admin iniciado no terminal aparecem nesse terminal; não pertencem automaticamente à unidade do broker.

Aula 8.4 — Prepare o token e crie contas web com permissões

Passo 1 — Crie arquivos privados e inicie o admin em loopback

Na mesma sessão Ubuntu da compilação, confira XMQR_ADMIN_BIN. Se abriu outro terminal, exporte novamente o caminho absoluto da fonte correta.

install -d -m 700 "$HOME/.config/xmqr-admin"
install -d -m 700 "$HOME/.config/xmqr-admin/auth"
if [ ! -e "$HOME/.config/xmqr-admin/access.token" ] && \
   [ ! -L "$HOME/.config/xmqr-admin/access.token" ]; then
  "$XMQR_ADMIN_BIN" token-init --file "$HOME/.config/xmqr-admin/access.token"
else
  printf '%s\n' 'Token já existe ou o caminho requer revisão; não foi sobrescrito.'
fi
export XMQR_ADMIN_TOKEN_FILE="$HOME/.config/xmqr-admin/access.token"
export XMQR_ADMIN_BIND=127.0.0.1:9080
export XMQR_ADMIN_MONITOR_BIND=127.0.0.1:9090
export XMQR_ADMIN_WEB_USERS_FILE="$HOME/.config/xmqr-admin/auth/users.json"
"$XMQR_ADMIN_BIN" serve

install -d -m 700 prepara diretórios acessíveis somente ao proprietário. O if impede substituir um token existente e também recusa confundir um link quebrado com caminho livre. token-init cria um token aleatório privado 600; não escreve uma senha web. Não use sudo para iniciar o admin da sua sessão Linux.

As variáveis escolhem o arquivo do token, o endereço do painel, o monitor e o modo de contas. A base users.json deve ser criada pelo programa: não grave um arquivo vazio manualmente. O diretório é 700; a base e seu lock são 600, regulares e sem links simbólicos. serve mantém o servidor no terminal; Ctrl+C encerra essa instância e seus filhos MQTT, preservando o broker independente. Se 9080 já estiver ocupada, identifique sua instância antes de iniciar outra.

Sem XMQR_ADMIN_WEB_USERS_FILE, permanece o modo anterior de token. Com a variável, o token Bearer antigo não contorna o login. Sem perfis MQTT configurados, o admin abre e mostra o console desabilitado; isso é esperado.

Passo 2 — Faça o primeiro cadastro, gerencie papéis e encerre sessões

Abra http://127.0.0.1:9080 no navegador do Windows. Se a base não tem usuários, surge o formulário do primeiro administrador. Em outro terminal Ubuntu, consulte o código local:

cat "$HOME/.config/xmqr-admin/access.token"

cat mostra o token apenas no seu terminal; copie-o diretamente para o campo do navegador. Não coloque o valor em URL, histórico de comandos, arquivo do curso, print público ou conversa. Use o token atual: um reset pode ter criado outro e um backup não é o arquivo ativo.

Defina sua própria conta: usuário ASCII de 3 a 32 caracteres (letras, números, _, -, normalizado em minúsculas), nome visível de 1 a 80 bytes e senha de 8 a 128 bytes sem controles. Escolha a senha diretamente no navegador, sem reutilizar a senha MQTT. Não há senha padrão. O primeiro cadastro cria um administrador e fecha o bootstrap; novos usuários são criados pela administração.

PapelMétricas e indicadoresConsole MQTT/payloadsContas web
viewerSimNãoNão
operatorSimSimNão
adminSimSimCriar, listar, ativar e desativar

Desativar uma conta revoga suas sessões; o último administrador habilitado não pode ser desativado. Contas web não criam usuários MQTT nem alteram ACL do broker. A senha é armazenada com Argon2id e salt aleatório; não é recuperável pela listagem. Alteração de senha, recuperação por e-mail e um broker diferente para cada conta web não fazem parte desta fatia.

A sessão usa cookie opaco com HttpOnly, SameSite=Strict e Path=/; o servidor mantém apenas o digest da sessão em memória. Há expiração absoluta de 8 horas e de inatividade de 30 minutos, até 64 sessões e 64 usuários, duas operações KDF paralelas e limite global de vinte tentativas de acesso por minuto. Escritas exigem CSRF e Origin/Host locais exatos; a interface envia esses dados automaticamente. Reiniciar o admin exige login novo. Use Sair do painel para revogar a sessão; se a rede falhar, a página informa que o logout no servidor não foi confirmado.

Aula 8.5 — Configure o console MQTT com perfis e senhas privadas

Passo 1 — Prepare CA, arquivos de senha e perfis separados

Faça isso somente depois de configurar um broker e usuários MQTT autorizados. O exemplo didático usa dht22-api para assinar e dht22-device para publicar dht22/readings; os nomes não provam que essas contas existam. Em uso compartilhado, prefira uma identidade de publicação própria do painel. As ACL devem autorizar cada operação; o admin não concede essas permissões automaticamente.

install -d -m 700 "$HOME/.config/xmqr-admin/mqtt"
test -f "$HOME/.config/xmqr-dht22/ca.crt"
install -m 600 "$HOME/.config/xmqr-dht22/ca.crt" \
  "$HOME/.config/xmqr-admin/mqtt/ca.crt"

test -f verifica a origem; se falhar, pare e localize a CA pública realmente usada pelo broker. install -m 600 copia essa CA para o perfil privado. Não gere uma CA diferente para tentar validar o mesmo certificado. Se já há uma CA no destino, confira-a antes de substituí-la; não copie a chave privada da CA para o console.

Crie senhas sem pô-las na linha de comando. Este bloco recusa sobrescrever arquivos existentes; a senha digitada é a credencial MQTT original, não o hash Argon2id do arquivo do broker.

(
  set -eu
  set -C
  umask 077
  for file in sub.password pub.password; do
    test ! -e "$HOME/.config/xmqr-admin/mqtt/$file"
    test ! -L "$HOME/.config/xmqr-admin/mqtt/$file"
  done
  read -r -s -p 'Senha MQTT da conta de assinatura: ' senha
  printf '\n'
  printf '%s' "$senha" > "$HOME/.config/xmqr-admin/mqtt/sub.password"
  unset senha
  read -r -s -p 'Senha MQTT da conta de publicação: ' senha
  printf '\n'
  printf '%s' "$senha" > "$HOME/.config/xmqr-admin/mqtt/pub.password"
  unset senha
)
chmod 600 "$HOME/.config/xmqr-admin/mqtt/sub.password" \
  "$HOME/.config/xmqr-admin/mqtt/pub.password"
nano "$HOME/.config/xmqr-admin/mqtt/sub.toml"
nano "$HOME/.config/xmqr-admin/mqtt/pub.toml"

O subshell (...) isola variáveis; set -eu interrompe erros e variáveis ausentes, set -C impede sobrescrita via redirecionamento, umask 077 restringe arquivos novos, read -r -s lê sem interpretar barras nem mostrar a senha. printf '%s' grava sem quebra extra e unset descarta a variável. chmod 600 garante leitura/escrita apenas ao proprietário. nano abre o editor; salve com Ctrl+O, Enter e saia com Ctrl+X. Se os arquivos já existem, revise-os em vez de executar a criação novamente.

Conteúdo de sub.toml, para um listener que já use TLS com senha sem certificado cliente:

version = 1
[connection]
tls_password = true
host = "127.0.0.1"
port = 8883
username = "dht22-api"
ca = "ca.crt"
password_file = "sub.password"
protocol_version = "3.1.1"

Conteúdo de pub.toml:

version = 1
[connection]
tls_password = true
host = "127.0.0.1"
port = 8883
username = "dht22-device"
ca = "ca.crt"
password_file = "pub.password"
protocol_version = "3.1.1"

version define o schema; [connection] agrupa conexão; host/port identificam o broker; username é a identidade MQTT; ca valida o servidor e password_file aponta a senha privada. Caminhos relativos partem da pasta do perfil. O nome/IP precisa estar no SAN do certificado: use localhost se esse for o nome autorizado, sem desativar validação TLS. Para mTLS, remova tls_password = true e informe também cert e key próprios da identidade, mantendo arquivos 600. Não altere o modo do broker só para encaixar o exemplo.

chmod 600 "$HOME/.config/xmqr-admin/mqtt/sub.toml" \
  "$HOME/.config/xmqr-admin/mqtt/pub.toml"

Os dois perfis devem ser regulares, não symlinks, privados e de até 64 KiB. Não escreva senha em TOML, variável de comando ou URL. Após reset, os perfis e a CA anteriores precisam ser restaurados com critério ou reprovisionados; a conta web nova não os recria.

Passo 2 — Teste pub/sub e habilite os perfis no admin

Em um terminal Ubuntu, use o mqtt-client aceito para esse marco:

mqtt-client sub \
  --profile "$HOME/.config/xmqr-admin/mqtt/sub.toml" \
  --topic dht22/readings --qos 1

sub assina; --profile carrega conexão/credenciais; --topic escolhe o filtro e --qos 1 solicita o nível da assinatura. Sem --count, o subscriber continua escutando até Ctrl+C ou uma falha/limite configurado. Uma mensagem não deve, por si só, encerrar essa assinatura.

Em outro terminal:

printf '%s' '{"temperature":24.6,"humidity":58.2}' | \
  mqtt-client pub \
  --profile "$HOME/.config/xmqr-admin/mqtt/pub.toml" \
  --topic dht22/readings --qos 1 --stdin

printf fornece um payload didático; o pipe o envia ao stdin do publicador. pub publica uma mensagem e encerra após sua confirmação de protocolo; --stdin lê o conteúdo até EOF. O assinante deve mostrar o JSON. Essa leitura foi produzida pelo comando, não por um sensor físico.

Encerre sua instância do admin com Ctrl+C antes de alterar seu ambiente. Na mesma sessão Ubuntu em que XMQR_ADMIN_BIN e as variáveis de acesso estão definidos:

export XMQR_ADMIN_MQTT_CLIENT_BIN=/usr/bin/mqtt-client
export XMQR_ADMIN_MQTT_SUB_PROFILE="$HOME/.config/xmqr-admin/mqtt/sub.toml"
export XMQR_ADMIN_MQTT_PUB_PROFILE="$HOME/.config/xmqr-admin/mqtt/pub.toml"
export XMQR_ADMIN_MQTT_LABEL='Laboratório DHT22'
"$XMQR_ADMIN_MQTT_CLIENT_BIN" --version
"$XMQR_ADMIN_BIN" serve

O caminho do client deve ser absoluto e apontar ao executável real aceito; ajuste /usr/bin/mqtt-client ao resultado verificado na sua instalação. O admin executa esse programa diretamente, sem shell e sem senha em argumentos; payloads publicados vão por stdin. O perfil PUB é separado do SUB; se omitido, o programa usa o perfil de assinatura também para publicar, o que pode não ter autorização adequada. O rótulo identifica a configuração, não é uma credencial.

No Console MQTT, escolha dht22/readings, QoS e Conectar e assinar. Aguarde SUBACK antes de considerar a assinatura ativa. Publique outro payload pelo editor ou pelo dispositivo. Use busca, pausa visual e limpeza local; pausar a exibição não pausa o broker. Desconectar afeta a assinatura compartilhada, não todos os assinantes externos.

Aula 8.6 — Interprete os indicadores e os limites operacionais

Passo 1 — Leia ON-LINE, OFF-LINE e estados sem confirmação

IndicadorQuando está ON-LINEO que não confirma
BrokerMonitor alcançável com resposta válida e pronto para operar (ready).Um monitor indisponível não prova que o MQTT morreu. Pode haver not_ready ou monitor_unavailable.
Client do consoleAssinatura compartilhada confirmada por SUBACK (connected).Não enumera ESP32, outros processos, clients instalados ou dispositivos externos.
XMQR AdminResposta autenticada válida de /api/status.Carregar HTML, ter o pacote instalado ou ver uma leitura antiga não comprova disponibilidade atual.

A tela inicia em Aguardando. Há consulta a cada ciclo de três segundos, somado ao tempo da requisição, sem ciclos sobrepostos. Falha de rede, timeout ou resposta inválida elimina estados anteriores: admin OFF-LINE e broker/client sem confirmação, sem afirmar que seus processos morreram. Falha isolada na lista de mensagens /api/mqtt não substitui um agregado válido de /api/status. Logout e troca de conta limpam indicadores.

Um viewer pode ver indicadores sem receber tópicos, payloads ou caminhos privados. A leitura agregada não renova o lease da assinatura. Ela expira em sessenta segundos sem consulta autorizada do console. Os estados connecting, disconnected, disabled e error não são confirmação de assinatura ativa.

Passo 2 — Conheça buffer, permissões, segurança e critérios do teste

A23 mantém uma assinatura compartilhada por instância, até duzentas mensagens no buffer e payload textual de até 4.096 bytes. Binários aparecem identificados como binários; payload maior é descartado com contagem. O console não é um arquivo histórico de telemetria. Conectar/desconectar/sair afeta o recurso compartilhado entre operadores autorizados. Publicações têm prazo limitado e não são repetidas automaticamente pela interface.

QoS 0 confirma envio local; QoS 1/2 confirma o intercâmbio MQTT com o broker. Isso não garante gravação em PostgreSQL, atualização do Google Sheets ou processamento pelo ESP32. Para provar o caminho completo, verifique cada etapa de aplicação com suas próprias evidências. O painel não apresenta controles fictícios para recursos administrativos ainda exclusivos do CLI.

HTTP fica em loopback, sem CORS aberto; Host/Origin, limites de corpo, autenticação e CSRF são verificados. A interface renderiza conteúdo remoto como texto e não como HTML executável. As contas web e suas sessões são independentes dos perfis MQTT privados. Se houver falha de certificado, SAN, senha ou ACL, corrija a causa; não desligue a proteção para deixar o indicador verde.

Para estudar com conforto, use o botão de tema claro/escuro deste guia. A preferência visual é local e não armazena credenciais. O recurso não muda o tema nem a segurança de outro sistema, e não é um botão de controle do broker.

Aula 8.7 — Faça reset com backup privado e exclusão conferida

Passo 1 — Pare sua instalação e mova somente configurações conhecidas

Procedimento opcional de reset, não de atualização da interface. Ele retira configurações e credenciais dos caminhos ativos, preserva pacotes instalados e /var/lib/xmqr. Um reset não restaura senha antiga, CA ou certificado automaticamente. Leia o bloco inteiro antes de escolher executá-lo. O curso não executa esses comandos por você.

Encerre com Ctrl+C os seus terminais de admin, subscriber e publisher ainda ativos. Se você usa o serviço broker da instalação que pretende resetar, pare-o explicitamente:

systemctl status xmqr-broker.service --no-pager
sudo systemctl stop xmqr-broker.service
ps -eo pid,comm

O primeiro comando verifica a unidade; stop interrompe esse serviço, sem desinstalar ou desativar a inicialização futura; o ps lista nomes e IDs de processos, sem imprimir argumentos que possam conter dados. Se a unidade não existe ou systemd não está ativo, identifique como sua instância foi iniciada e pare apenas a sua. Não use kill geral nem reinicie programas de outro usuário. Só continue quando a área estiver inativa.

O bloco seguinte usa uma lista fixa de pastas, um destino novo e privado e variáveis definidas no mesmo subshell. Ausências são normais após um reset anterior. Links simbólicos e caminhos inesperados são recusados.

(
  set -eu
  umask 077
  if pgrep -x 'mqtt-broker|mqtt-client|xmqr-admin' >/dev/null; then
    printf '%s\n' 'Ainda há processo XMQR; confira e pare somente sua instalação.'
    exit 1
  fi
  fontes=(
    /etc/xmqr /etc/xmqr-client /etc/xmqr-admin
    "$HOME/.config/xmqr" "$HOME/.config/xmqr-client"
    "$HOME/.config/xmqr-admin" "$HOME/.config/xmqr-dht22"
    "$HOME/xmqr-certificados"
  )
  for origem in "${fontes[@]}"; do
    test ! -L "$origem"
    if [ -e "$origem" ]; then
      test -d "$origem"
      test "$(sudo realpath -e -- "$origem")" = "$origem"
    fi
  done
  backup="$(sudo mktemp -d /var/backups/xmqr-reset-XXXXXXXX)"
  case "$backup" in /var/backups/xmqr-reset-*) ;; *) exit 1 ;; esac
  test "$(dirname -- "$backup")" = /var/backups
  test -d "$backup"
  test ! -L "$backup"
  test "$(sudo realpath -e -- "$backup")" = "$backup"
  sudo chmod 700 "$backup"
  sudo mkdir -m 700 "$backup/etc" "$backup/user-config" "$backup/user-home"
  for origem in "${fontes[@]}"; do
    if [ ! -e "$origem" ]; then
      printf 'Ausente, preservado como está: %s\n' "$origem"
      continue
    fi
    case "$origem" in
      /etc/xmqr|/etc/xmqr-client|/etc/xmqr-admin)
        destino="$backup/etc/$(basename -- "$origem")" ;;
      "$HOME/.config/xmqr"|"$HOME/.config/xmqr-client"|"$HOME/.config/xmqr-admin"|"$HOME/.config/xmqr-dht22")
        destino="$backup/user-config/$(basename -- "$origem")" ;;
      "$HOME/xmqr-certificados") destino="$backup/user-home/xmqr-certificados" ;;
      *) exit 1 ;;
    esac
    real_origem="$(sudo realpath -e -- "$origem")"
    case "$backup/" in "$real_origem/"*) exit 1 ;; esac
    sudo test ! -e "$destino"
    sudo test ! -L "$destino"
    sudo mv -T -- "$origem" "$destino"
  done
  printf 'Backup privado criado: %s\n' "$backup"
)

fontes é uma lista Bash fechada; não há movimento por wildcard. A primeira passagem valida as origens. mktemp -d cria uma pasta nova com sufixo real, sem depender de um nome fictício. dirname e realpath -e conferem o destino absoluto; test ! -L recusa links. mkdir -m 700 prepara grupos privados de backup. O segundo case define destinos permitidos e impede mover uma pasta para dentro dela própria. mv -T move a pasta para o destino exato, sem substituição de uma pasta já presente.

O backup continua contendo segredos e deve ficar privado; não o publique. Se houver erro depois de algum movimento, pare e confira o destino informado: não repita cegamente nem apague o backup. Nenhum passo acima remove pacotes ou o estado persistido MQTT. Reutilizar estado antigo exige configuração/identidades compatíveis e um procedimento de restauração validado; não inicie o broker com arquivos faltando nem presuma que suas credenciais anteriores foram recriadas.

Depois do reset, a configuração web da Aula 8.4 — Prepare o token e crie contas web com permissões cria um token novo e permite um primeiro cadastro novo. Refaça ou restaure conscientemente os perfis da aula 8.5; o admin pode funcionar com console desabilitado enquanto isso. Voltar apenas um arquivo de usuários não restaura todos os certificados, ACL e senhas MQTT.

Passo 2 — Escolha o backup real antes de excluir definitivamente

Exclua somente quando tiver confirmado que não precisa mais restaurar aquela cópia. Primeiro liste os diretórios candidatos; a listagem não exclui nada:

sudo find /var/backups -mindepth 1 -maxdepth 1 -type d \
  -name 'xmqr-reset-*' -print

find pesquisa apenas um nível sob o diretório fixo. Copie um caminho real da sua saída. Não copie um sufixo ilustrativo nem acrescente barras extras. O próximo bloco pede o caminho e confere raiz, nome, existência, tipo e resolução antes de remover.

(
  set -eu
  read -r -p 'Cole o caminho completo do backup real a excluir: ' backup
  case "$backup" in /var/backups/xmqr-reset-*) ;; *) exit 1 ;; esac
  test "$(dirname -- "$backup")" = /var/backups
  nome="$(basename -- "$backup")"
  [[ "$nome" =~ ^xmqr-reset-[A-Za-z0-9._-]+$ ]]
  test -d "$backup"
  test ! -L "$backup"
  test "$(sudo realpath -e -- /var/backups)" = /var/backups
  test "$(sudo realpath -e -- "$backup")" = "$backup"
  sudo ls -ld -- "$backup"
  sudo rm -rI -- "$backup"
)

read -r lê sua escolha sem interpretar barras. O case permite apenas o prefixo de backup; dirname impede caminhos aninhados ou saída da raiz. A expressão regular limita o nome. -d exige um diretório existente; ! -L recusa symlink; os dois realpath conferem a raiz e o destino final. Só depois rm -rI pede confirmação única para remover recursivamente a pasta escolhida. Em prompt y/n em inglês, responda y para confirmar ou n para cancelar; s não significa yes. Não há wildcard destrutivo.

Se o caminho não existir, a validação interrompe o bloco; isso não prova perda de dados. Liste novamente e confira o nome, o diretório e se a cópia já foi movida ou removida. Não substitua o comando por rm -rf nem remova a raiz /var/backups. A exclusão elimina a possibilidade de restaurar esse backup.
