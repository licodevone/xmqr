# XMQR broker 0.22.0 — metadados de PUBLISH MQTT 5 (experimental)

P141/P142 encaminham Payload Format Indicator, Content Type, Response Topic, Correlation Data binária e User Property repetível em ordem no PUBLISH MQTT 5. As propriedades são preservadas em QoS0/1/2, mensagens retidas, fila offline e replay após reinício. O assinante MQTT 3.1.1 recebe somente tópico e payload. O `mqtt-admin` legado acompanha a versão; o `xmqr-admin` independente permanece 0.4.0. Client parceiro 0.20.0.

**Migração e rollback:** o documento durável passa de v8 no broker publicado 0.21.0 para v10 após P141/P142. Faça backup offline privado antes de atualizar. Para voltar a 0.21.0, pare o serviço, restaure o estado v8 do backup anterior à primeira gravação nova e reinstale o pacote anterior. O estado v10 não abre em 0.21.0; um estado v9 intermediário tampouco. Confira o manifesto e SHA-256 dos anexos antes de instalar. O release não altera a instalação WSL do operador.

**Limites:** Response Topic precisa ser tópico válido sem curingas (até 1024 bytes); Correlation Data aceita até 256 bytes; User Property aceita até 16 pares em ordem, cada campo até 256 bytes e até 2048 bytes codificados. O broker não valida o payload UTF-8 anunciado por Payload Format Indicator 1, escolha permitida ao receptor. O `mosquitto_sub` 2.0.22 ainda rejeita a forma abreviada válida de Topic Alias de saída; essa direção não está homologada. Outras propriedades MQTT 5, opções de assinatura, shared subscriptions, AUTH, WebSocket, bridge e Windows nativo continuam pendentes. Não há alegação de conformidade MQTT 5 integral; fases 6A–6D e 7–9 permanecem abertas. Docker `latest` permanece intacta.

Validação prevista: gates Rust, pacote Ubuntu26, TCP real QoS0/1/2, retained/offline/restart, interop com client e Mosquitto, regressões de limites e alias, ciclo de pacotes e CI.
