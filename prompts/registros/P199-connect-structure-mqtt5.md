# P199 — CONNECT MQTT 5 estruturalmente inválido

- [Prompt P199](../broker/199-connect-structure-mqtt5.md) criado e enviado antes do código em `e614d70`. Entrada: broker/admin legado 0.35.0 publicado, estado v15, árvore limpa; client independente 0.28.0 e admin independente 0.10.0 preservados.
- Implementação `51ae55964da0957ba0604c70d412462bf3e0d9aa`, enviada a `origin/main`: classifica `MalformedPacketStructure` de CONNECT inicial MQTT 5 somente quando protocolo e bloco CONNECT Properties estão íntegros. O limite Maximum Packet Size é obtido apenas das fronteiras válidas desse bloco; `0x27` em texto ou binário não é interpretado como propriedade. O broker devolve CONNACK `0x81` se couber nos cinco bytes mínimos e fecha sem sessão/Will. MQTT 3.1.1 conserva fechamento sem resposta MQTT 5.
- A primeira versão do ensaio TCP falhou porque a própria conexão de controle criava sessão persistente entre casos; foi corrigida para Session Expiry zero. A primeira suíte Rust completa encontrou duas expectativas antigas de fechamento silencioso para campos Will estruturalmente malformados; ambas foram atualizadas para CONNACK `0x81`, mantendo o erro semântico de Topic Name inválido. Clippy inicialmente rejeitou `Option<Option<u32>>`; o retorno foi simplificado para `Result<Option<u32>, MalformedPacketStructure>` e passou.
