# P144 — Receive Maximum do broker no CONNACK MQTT 5

- [Prompt P144](../broker/144-connack-receive-maximum-mqtt5.md) criado antes do código. Base 0.22.0 aceita; fase 6C aberta.
- Implementação: CONNACK MQTT 5 anuncia Receive Maximum (`0x21`) 1..32 conforme `MQTT_MAX_INFLIGHT`, quando há três bytes disponíveis além das propriedades existentes. MQTT 3.1.1 não muda. Para Maximum Packet Size do client 5..7, 10..15, a propriedade é omitida para preservar os fallbacks P136/P138; 8..9 e >=16 a incluem. Isso ainda não elimina a lacuna de flow control na retomada de QoS2 com quota durável cheia.
- Gates locais: vetor de codec com limite 1/32 e cinco fixtures de CONNECT atualizadas; suíte Rust (164 library + 23 integração PASS, seis ignorados), TCP real em [verify_mqtt5_connack_receive_maximum.py](../../scripts/verify_mqtt5_connack_receive_maximum.py) com limites 5/7/8/9/10/12/13/15/16, QoS0/1/2, excesso QoS2 sem commit parcial, restart, client XMQR e Mosquitto 2.0.22 PASS. Regressões P134/P136/P138/P139 PASS. `cargo fmt --check`, Clippy, build release e inventário de licenças PASS.
