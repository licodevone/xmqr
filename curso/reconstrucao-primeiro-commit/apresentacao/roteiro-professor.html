Slide 4 — Rust, rustc e Cargo têm funções distintas

Seção 0 — Rust, C e o caminho até o executável
Aula inicial

Fala sugerida aos alunos

Rust é a linguagem: suas regras dizem como escrever e interpretar o programa. rustc é o compilador. Cargo é a ferramenta que coordena o pacote, as bibliotecas e os comandos de construção e teste. Quando pedimos cargo build, Cargo descobre o que precisa ser compilado e aciona rustc. Depois de gerar o executável, podemos rodá-lo. Compilar e executar são momentos diferentes. Arquivo fonte é texto editável; executável contém instruções para um alvo.

Orientações privadas ao apresentador

Pronuncie rustc como compilador Rust. Reforce que Cargo não substitui o compilador. Conecte esta distinção aos comandos que o aluno verá na Aula 1.

Slide 5 — O pipeline simplificado do rustc

Seção 0 — Rust, C e o caminho até o executável
Aula inicial

Fala sugerida aos alunos

O compilador lê o texto e monta estruturas internas. AST significa árvore de sintaxe abstrata. HIR é uma representação de alto nível usada para análises do programa. MIR é uma representação intermediária de nível médio, utilizada também pela verificação de empréstimos. No backend padrão, o código segue para LLVM IR, passa por otimizações e vira código objeto. O linker combina os objetos e bibliotecas para gerar o executável. O aluno não precisa memorizar todas as siglas agora: precisa reconhecer a função de cada transformação.

Orientações privadas ao apresentador

Aponte da esquerda para a direita. Não situe o borrow checker somente antes de MIR: a análise de empréstimos usa MIR. Não afirme que LLVM é o único backend possível.

  • https://rustc-dev-guide.rust-lang.org/overview.html
  • https://rustc-dev-guide.rust-lang.org/backend/codegen.html

Slide 6 — LLVM reutiliza etapas entre linguagens

Seção 0 — Rust, C e o caminho até o executável
Aula inicial

Fala sugerida aos alunos

O front-end entende uma linguagem e representa corretamente o que seu programa significa. IR é representação intermediária, uma forma que ferramentas podem analisar. O otimizador aplica passes, que são etapas de análise ou transformação. O backend escolhe instruções para o alvo. Essa organização permite compartilhar infraestrutura entre compiladores de linguagens diferentes. O IR possui regras precisas, e cada front-end precisa respeitá-las. Não precisamos executar centenas de passes em todo build nem obter o programa mais rápido possível em qualquer situação.

Orientações privadas ao apresentador

Explique cada termo antes da sigla. LLVM IR não é um idioma humano nem uma máquina virtual que os usuários do broker precisam instalar para executar o binário.

Slide 8 — C também passa por etapas de compilação

Seção 0 — Rust, C e o caminho até o executável
Aula inicial

Fala sugerida aos alunos

No fluxo tradicional do GCC, o pré-processador expande inclusões e macros. O compilador transforma o programa, o assembler converte instruções assembly em objetos e o linker liga esses objetos e bibliotecas. O comando pode integrar tudo sem que o programador veja arquivos intermediários. C continua atual e possui vários compiladores. Clang também usa LLVM. Slide 10 — Memória: controle explícito e propriedade

Seção 0 — Rust, C e o caminho até o executável
Aula inicial

Fala sugerida aos alunos

Em C, quando usamos alocação dinâmica com malloc, precisamos determinar quando liberar o recurso com free e garantir que nenhum acesso inválido continue. Rust usa propriedade e empréstimos para restringir acessos e duração. Uma referência empresta acesso sem receber a propriedade. Recursos associados a valores como String normalmente são liberados ao sair do escopo. Nem todo valor usa memória dinâmica, e Rust também não precisa de um coletor de lixo periódico para seu modelo de propriedade.

Orientações privadas ao apresentador

Defina ponteiro como valor que identifica uma posição de memória. Não diga que todo tipo Rust aloca heap ou que vazamentos são impossíveis. Explique escopo como a região onde uma variável é válida.

Slide 11 — Segurança de memória tem limites claros

Seção 0 — Rust, C e o caminho até o executável
Aula inicial

Fala sugerida aos alunos

Data race é um conflito de acessos concorrentes à mesma memória sem sincronização adequada, com pelo menos uma escrita. Rust seguro impede essa categoria nas garantias da linguagem, mas não impede toda falha concorrente. Também pode haver vazamentos e deadlocks. Um acesso fora dos limites pode causar panic em execução. Overflow numérico é diferente de acessar memória fora de uma região: existem operações com comportamento explícito e opções de checagem. O compilador ajuda muito, mas não substitui testes de MQTT ou decisões de disponibilidade do serviço.

Orientações privadas ao apresentador

Distingua buffer overflow de overflow de inteiros. Qualifique as garantias em relação a abstrações seguras corretamente implementadas. Não projete conclusões de segurança do broker sem testes.

Fontes

  • https://doc.rust-lang.org/nomicon/leaking.html
  • https://doc.rust-lang.org/reference/expressions/operator-expr.html#overflow
  • https://doc.rust-lang.org/book/ch16-00-concurrency.html

Slide 12 — Rust e C: vantagens e desafios

Seção 0 — Rust, C e o caminho até o executável
Aula inicial

Fala sugerida aos alunos

Rust traz ferramentas integradas e regras de propriedade que ajudam a estruturar serviços. O custo inicial inclui aprender empréstimos, lifetimes e traits. Slide 13 — Hardware e integração com código existente

Seção 0 — Rust, C e o caminho até o executável
Aula inicial

Fala sugerida aos alunos

Rust pode trabalhar em sistemas embarcados sem toda a biblioteca padrão, usando no_std. O suporte precisa ser confirmado para cada hardware e biblioteca. FFI significa interface com funções estrangeiras e permite integrar APIs de outras linguagens. Algumas operações nessa fronteira exigem unsafe. Isso não desliga todas as verificações nem o borrow checker. O programador assume contratos específicos que o compilador não consegue provar. Bibliotecas podem encapsular essa fronteira em uma interface segura. No XMQR seguiremos a regra do projeto que proíbe adicionar código unsafe próprio.

Orientações privadas ao apresentador

Evite transformar unsafe em recomendação para contornar erros de compilação. Mostre que escolher Rust não elimina a necessidade de verificar suporte ao dispositivo.

Slide 18 — Gravação durável com um escritor

Aula 3 — Persistência e ator, R03

Slide 20 — Conexões TCP e proteção TLS

Slide 22 — O codec transforma bytes em pacotes

Seção 3 — Construir o núcleo MQTT, R06
Aula 6 — Ler e produzir pacotes: codec.rs

Fala sugerida aos alunos

Digite codec.rs seguindo as funções de leitura e de escrita do guia. O codec verifica comprimento e campos antes de transformar bytes em estruturas Rust. Um byte é uma unidade de oito bits, e as flags representam opções dentro desses bits. Match seleciona o tratamento de cada alternativa e Result diferencia sucesso de erro. Slide 28 — Administração local de usuários

Seção 4 — Integrar os programas executáveis
Aula 11 — Administrador, R08

Fala sugerida aos alunos

Cargo reconhece executáveis adicionais dentro de src/bin. Digite o arquivo do administrador e verifique a ajuda antes de operar usuários. A opção bin seleciona qual executável Cargo vai rodar. Os dois hífens separam opções do Cargo das opções do programa. Rpassword lê a senha sem mostrá-la no terminal. Operações atômicas de usuários dependem de Unix nesse código histórico, então a compilação no Windows não prova que esse fluxo executa nele. Use WSL para o laboratório previsto.

Orientações privadas ao apresentador

Não criar usuários reais durante a apresentação. Se demonstrar, siga o perfil fictício e a pasta de estado do laboratório. --help não pede credenciais.

Slide 29 — Publicação e assinatura pelo client

Seção 4 — Integrar os programas executáveis
Aula 12 — Client, R09

Fala sugerida aos alunos

Crie src/bin/mqtt-client e digite os cinco arquivos na ordem R09. CLI significa interface de linha de comando. A CLI valida argumentos, o módulo de credenciais cuida de entradas sensíveis, TLS configura certificados e session coordena a comunicação. Rumqttc oferece o cliente MQTT e seu processamento de eventos. Futures-util fornece utilidades assíncronas utilizadas pelo projeto. Publicar envia uma mensagem para um tópico; assinar pede que mensagens desse tópico sejam entregues ao cliente. O broker fica entre os clientes.

Orientações privadas ao apresentador

Mostre que o cliente não entrega diretamente a outro cliente. Se alguma biblioteca surgir pela primeira vez, abra sua explicação em BIBLIOTECAS.md antes de digitar a chamada.

Slide 32 — Cada comando responde a uma pergunta

Seção 5 — Completar os arquivos, validar e criar o commit, R10
Aula 14 — Validar o código final

Fala sugerida aos alunos

Build produz os executáveis. Check verifica os alvos sem terminar todo o processo de geração do binário. Fmt confere estilo e test executa os testes. Clippy é um analisador que aponta problemas e sugestões. Menos D warnings transforma avisos em erros nesse comando. A validação histórica passou build e check no Windows e Ubuntu, e 52 testes Linux. Clippy 1.99 apontou assert_is_empty no snapshot original. O guia mostra a correção em cópia separada, mantendo R10 fiel ao commit. Um erro de lint não significa que o programa deixou de compilar.

Orientações privadas ao apresentador

A aula usa os resultados registrados, não um resultado novo desta apresentação. Evite anunciar PASS geral no snapshot original porque seu Clippy falhou. Mostre VALIDACAO.json se perguntarem.

Slide 33 — Três terminais verificam a comunicação

Seção 5 — Completar os arquivos, validar e criar o commit, R10
Aula 15 — Pub/sub no laboratório local Ubuntu/WSL

Fala sugerida aos alunos

Abra três terminais no Ubuntu ou WSL. Primeiro inicie o broker em open-lab, com endereço loopback, porta 18839 e estado fora da pasta do projeto. Slide 34 — O commit registra uma versão revisada

Seção 5 — Completar os arquivos, validar e criar o commit, R10
Aula 16 — Criar seu primeiro commit

Fala sugerida aos alunos

Git init cria o repositório local do exercício com a branch main. Status mostra o que mudou. Add coloca arquivos na área de preparação, e diff cached permite revisar exatamente o que será registrado. Antes de commit, confira que não entraram estado de execução, certificados ou senhas. Commit cria o registro local. Seu SHA será diferente do histórico mesmo que os arquivos sejam iguais, porque metadados participam do identificador. Não faça force push nem substitua o repositório real do XMQR para realizar este exercício.

Orientações privadas ao apresentador

Se identidade Git estiver ausente, configure-a apenas no exercício conforme o guia. Não reaproveitar identidade fictícia de ensaio como identidade do aluno. Não executar este comando no repo real durante gravação.
